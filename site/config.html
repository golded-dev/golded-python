00

golded.toml

TOML in the current directory, or the path given with --config. A missing file means defaults. Every field is optional.

golded.toml.example
# Copy to golded.toml and edit.
# Used when you start the app and when you write or reply.

from_name = "Odinn"
from_address = "2:236/777"
database = "messages.sqlite3"
origin = "Where we're going, we don't need roads."
theme = "dark"
threaded_list = false
splash_seconds = 10

# Optional message areas. Paths are relative to this file.
# [jam]
# read_mode = "strict"
#
# [areas]
# "FIDONET.GENERAL" = { description = "General discussion", group = "A", type = "echo", format = "jam", path = "bases/general", read_mode = "lenient" }

Command-line options

Options override the file.

OptionDefaultMeaning
--config PATHgolded.tomlUser config file
--database PATHfrom configOpen one SQLite message base, overriding the TOML message source.
--area-config PATHnoneRead AREADEF entries instead of opening one base.
--readonlyoffBrowse areas with new messages and replies disabled. Overrides an area's write mode. Combine with --debug to check archived bases.
--debugoffCheck each area and report readable message counts on stderr before opening the UI. Squish reports unlinked frames and the configured write mode. Use 2>golded-debug.log to keep the report.

03

Message areas in golded.toml

Put each area in an inline table under [areas]. The key is the area ID. Quote IDs containing dots so TOML treats the full ID as one key. Areas appear in declaration order.

golded.toml
[jam]
read_mode = "strict"

[areas]
ARCHIVE = { description = "Archive", group = "A", type = "echo", format = "jam", path = "bases/archive", read_mode = "lenient" }
"FIDONET.GENERAL" = { description = "General discussion", group = "A", type = "echo", format = "jam", path = "bases/general" }
LOCAL = { description = "Local discussion", group = "A", type = "echo", format = "sqlite", path = "bases/local.sqlite3" }

Each entry requires description, group, type, format and path. Use a group of A–Z, 0 or #1–#999 as a quoted string. Use echo or net for the type, and jam, squish, msg, opus, hudson or sqlite for the format. Paths are relative to the TOML file unless absolute. The classic area rules also apply to SQLite area matching, JAM base filenames and JAM writes.

A JAM area's read_mode overrides [jam].read_mode. Both accept strict or lenient and the built-in default is strict. Squish defaults to strict. Set read_mode = "archive" on a Squish area to browse recoverable messages with automatic write protection. The area status shows recovered deviations, skipped records and stopped traversals. --debug also lists the diagnostic categories. Archive mode takes precedence over the area's write mode. On a Squish archive area, add msgid_conflict = "display" to show messages with conflicting MSGIDs. GoldED warns in the message view and uses the index UID as the message identity.

With neither source option, a nonempty [areas] table takes precedence over database. With no areas, GoldED uses database or defaults to messages.sqlite3. An explicit --database or --area-config uses its own message source and skips [areas] and [jam] while still loading TOML preferences.

04

Classic area configuration

Run golded --area-config golded.cfg to list areas from existing SQLite, JAM, Squish, MSG, Opus and Hudson bases in configuration order. This option replaces the TOML database setting and cannot be combined with --database. Keep identity, origin and display preferences in golded.toml.

golded.cfg
AREADEF GENERAL "General discussion" A Echo SQLite "bases/echo.sqlite3" . ()
AREADEF NETMAIL "Private mail" #117 Net SQLite bases/mail.sqlite3 . ()
AREADEF UNIX "UNIX discussion" A Echo JAM bases/UNIX . ()
AREADEF LINUX "Linux discussion" A Echo Squish bases/LINUX . ()

Each AREADEF line gives the echo ID, quoted description, group, type, format and path. The group is a letter A–Z, 0, or #1–#999. Use Echo or Net. For SQLite, the type and echo ID must match an existing area. Echo IDs are matched without regard to ASCII case and must be unique in the configuration. Paths are relative to the configuration file unless absolute. Save the file as UTF-8.

SQLite is a GoldED.py extension. For JAM, use the base filename without the extension. Each JAM base represents one area and needs its existing .JHR, .JDT and .JDX files. Suffixes may be lowercase. GoldED checks the base on startup and reports invalid records. It uses the declared charset when reading, falls back to CP850, and writes in CP850. Characters outside CP850 stop the save and leave the draft open. Keep the base closed in other programs while using it here. A read-only base supports browsing.

JAMREAD strict sets the global JAM read mode. Strict is also the built-in default. Use JAMREAD lenient to change the default for all JAM areas, or JAMREAD UNIX lenient to override it for the UNIX area. An area override takes precedence regardless of directive order. Echo IDs in overrides use the same matching rules as AREADEF.

Lenient mode keeps recoverable records and can skip invalid records or stop at an ambiguous index entry. Highlight the area to see counts of recovered deviations, skipped records and stopped traversals in the status bar. A stopped traversal may show only part of the base. JAM writing still validates the entire base strictly. If that check fails, the composer shows the error and keeps the draft open.

For Squish, use the base filename without the .SQD or .SQI suffix. Both files must exist; lowercase suffixes also work. Each base represents one area. Keep it closed in other programs while GoldED uses it. Reads honor the declared charset with CP850 as the fallback. Writes use CP850 and reject unencodable text and names or subjects that exceed the format's field sizes. Replies store the parent message UID. Set write_mode = "allow_unlinked_append" on an individual Squish area in TOML to append past unlinked frames. The existing frames are preserved and strict writing is the default.

For MSG, give the directory that holds the numbered .MSG files, for example AREADEF NETMAIL "Netmail" A Net MSG bases/netmail. GoldED opens one classic FTSC area per directory, reads both uppercase and lowercase file extensions, and writes uppercase extensions. It uses CP850 for writes and for reads without a charset declaration. The reply field can refer to message numbers up to 65535. For Opus headers, use Opus in AREADEF or format = "opus" in TOML. Opus timestamps use two-second precision. It is safe to browse in --readonly mode. Close the area in other programs before writing to it here.

Hudson stores multiple boards in a single base directory. In classic configuration, set HUDSONPATH bases/hudson once and give the board number in each AREADEF, for example AREADEF TEST "Test" A Echo Hudson 7. In TOML, set format = "hudson", path = "bases/hudson" and board = 7. Board numbers run from 1 to 200. New messages and replies go to the configured board. With --readonly, GoldED loads the Hudson base at startup. Restart GoldED to see later changes. Close the base in other programs before writing.

The optional classic tail aka (attrs) [origin] and group are accepted without applying area-specific settings. Semicolons outside quoted fields start comments. Other directives, including INCLUDE and AREAFILE, are ignored. Use literal paths on the current system.

05

Invalid values

A config golded cannot use stops it at startup with Cannot read config PATH: … and exit status 1: malformed TOML, an invalid from_address, an unknown theme, a threaded_list that is not true or false ("no" is a string, and an error), or a splash_seconds that is not a whole number of 0 or more.
